# Reproducing the reported results

All primary results can be recomputed from the saved files. Reanalysis does not require calling Claude, GPT, Gemini, DeepSeek or Kimi again.

## Environment

Use Python 3.11 or later. The release was verified on Python 3.12.14 with the four direct dependencies pinned in `requirements.txt`: NumPy, SciPy, pandas and matplotlib. These pins describe the verified analysis environment, not a recovered environment from the original collection.

From the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

The activation command above is for macOS/Linux. On Windows PowerShell, use `.venv\Scripts\Activate.ps1`.

Run the commands below from the repository root. Some scripts locate inputs through the working directory; others locate them beside the source file. Keep the CSV/JSONL inputs and runnable scripts in their supplied locations.

`analyze.py` also writes generated plots and tables to `charts/`; the sensitivity variant writes `charts_sensitivity/`. Those are derived outputs. Analysis does not change the saved response files.

For the paper's feedback analysis, include **both** `results_feedback.jsonl` and `detection.csv`. Omitting the grading file drops H3 and changes the multiple-testing correction family. It is not the analysis reported in the paper.

## Replay and figures

```bash
python3 replay_check_strict.py --output local_runs/replay_check_strict.json
python3 figures/make_figure1.py
python3 figures/make_figure_a1.py
```

Strict replay replaces model responses with the saved replies and blocks network calls. It checks model IDs, message roles/content, stored fields, follow-up rounds, expected call counts and records without transcripts across supported snapshots. It is not a new model evaluation.

Expected result: **12,080 record-version checks, zero mismatches**, including all 3,280 records through the final runner. The preserved result is `audit/replay_check_strict.json`; new local output goes into the ignored `local_runs/` directory.

The figure scripts contain reviewed numeric summaries taken from analysis outputs. Regenerating an identical PNG confirms rendering reproducibility; it is not an additional independent calculation of every plotted count.

## What was checked for this release

All ten commands above passed in an isolated copy with network calls blocked. Seven analysis stdout outputs matched their saved references exactly, and both paper figures regenerated byte-for-byte. Collection scripts and saved data were unchanged. See `audit/packaging_validation.txt` and `.json`.

## Collecting new responses (optional, makes paid API calls)

New collection is unnecessary for reproducing the report. Model behavior, model availability and provider defaults may change; new replies can differ even at temperature 0.

`fliprate.py` writes outputs **beside its own file** and resumes existing result files. Changing only the terminal's working directory does not isolate a new experiment. Use a separate copy or checkout of the runner and its required materials, and keep the published response files unchanged. A complete repeat should use new output files for every stage; the timing experiment depends on the Experiment 1 control answers.

| Command | Purpose |
| --- | --- |
| `python3 fliprate.py run` | Experiment 1 |
| `python3 fliprate.py run-args` | Experiment 2, using `arguments.csv` |
| `python3 fliprate.py run-timing all` | Experiment 3, using saved control answers and arguments |
| `python3 fliprate.py run-feedback` | Experiment 4, using the final `essays.csv` |

Collection reads `OPENROUTER_API_KEY` from the environment or a local `.env` file. API credentials do not belong in the repository. The `smoke`, `smoke-args`, `smoke-timing` and `smoke-feedback` commands also call the real API. Argument/essay generation commands create new materials; they are separate from reusing the frozen materials in this archive.

The original final runner and historical snapshots are preserved for inspection. Their recorded compatibility does not prove the exact unlogged historical provider configuration; see `PROVENANCE.md`.
