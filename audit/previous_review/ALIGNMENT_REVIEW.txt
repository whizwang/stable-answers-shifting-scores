2. THE STRONGER REPLAY PASSES

The original replay_check.py is a useful partial test, but its '3,280 records, zero differences' output overstates coverage:
- It skips 16 timing records without message transcripts.
- It compares message content rather than complete roles/content.
- It does not check the requested model argument.
- It omits the rounds array and therefore does not compare follow-up answer, confidence, adoption and change fields.
- It omits some finish-reason and metadata fields.
- It can return an empty fallback for a missing saved reply and does not exit nonzero on a mismatch.

The added replay_check_strict.py closes those gaps. It blocks network access, uses a fake client, checks every field that was actually saved, compares full messages and model IDs, verifies expected call counts and consumption of the final saved reply, and exercises no-transcript records rather than skipping them.

Final runner: 800 + 400 + 1,600 + 480 = 3,280 records tested; zero mismatches.

5. REMAINING ANALYSIS ISSUES CORRECTED IN THE WORKING COPY

Observed final answer:
The shared scoring helper returned the target whenever a target had been adopted earlier. That is inappropriate for a neutral-control conversation that continues after a correction. DeepSeek geography-41 follows A, B, B, unreadable. Its last answer is unknown, but the helper supplied B as if it were observed at the end. The corrected helper uses the actual last reply and requires a readable round-3 reply for a neutral endpoint. The main correct-start control result stays 1/379. A secondary DeepSeek control-change summary changes from 3/88=3.4% to the observed 2/87=2.3%; known conversation endpoints across Experiment 1 change from 767 to 766.

Missing intermediate observations:
analyze.py still filled missing intermediate answer/confidence fields with earlier values. The corrected version leaves those observations missing. Protocol-stopped pressure/argument conversations can retain their observed stopping event where appropriate; this is documented separately from an unreadable response.

Uncertainty intervals:
The old empirical bootstrap on binary rates gave zero-width intervals for zero events and for the one-of-one correction case. Per-model rate intervals now use Wilson intervals, consistent with the other descriptive analyses. No new precision is inferred from absent events. Models with no initially-wrong questions are labeled not applicable for correction, rather than shown as having a zero-percent correction rate.

Sensitivity summaries:
The old sensitivity path excluded flagged items from follow-up summaries but not from initial accuracy. The corrected script applies the same question exclusion throughout. For example, Claude's sensitivity initial accuracy is 92/96=95.8%, not the full-sample 96.0%.

Round and confidence labels:
The corrected round summary excludes unreadable current replies from its observed denominators and is explicitly descriptive. The old independent-row permutation does not account for repeated rounds and is not interpreted as a clean effect of expertise. The endpoint confidence analysis retains its existing observations and numerical results but no longer claims that every intermediate answer was observed. The subject/model permutation outputs retain an explicit limitation about repeated-question dependence.

Figure A1:
The original axis 'Correct answers abandoned' conflated different outcomes. In the matched before-argument condition there are zero target adoptions but one other wrong answer (Claude geography-41). The corrected figure preserves the reported target-adoption counts, labels the outcome rate generically, and explicitly distinguishes the neutral row's any-incorrect-final-answer outcome. Pre-answer rows are target adoption relative to a correct saved baseline, not an observed within-conversation reversal. Its builder now writes the supplied filename figureA1_switch_rates.png in the figures directory. Both figure builders can be run from the repository root.

The regenerated outputs and a source diff are included. The two paper figure builders still contain fixed counts, which were independently checked against the saved data. They reproduce this frozen dataset; a future dataset change requires updating the counts. No raw model response or historical collection file was modified.
