README CLAIMS TO NARROW

1. 'Each version only added code' remains literally false across the entire history.
   Exp1 -> first argument pass: 178 inserted and 11 removed lines, with changes to OpenRouter, run_one and run.
   First argument pass -> Exp2: 7 inserted and 4 removed lines, with changes to make_arguments and check_arguments plus the budget constant.
   Exp2 -> Exp3: 106 inserted, 0 removed, no existing definitions changed.
   Prefer: 'The runner was extended as experiments were added. Some existing functions were modified to add optional arguments, finish-reason logging and generation controls. The archived versions and offline replay checks allow the earlier experiment behavior to be compared.' Then make only the specific unchanged-behavior claims actually verified by the runner audit.

2. 'Stricter argument check' is not uniformly accurate. The first-pass checker flagged any occurrence of option A/B/C/D, even the selected option. The new checker permits mention of the selected option and detects other options using option/answer/choice wording. Prefer 'target-aware argument validation'. It is a diagnostic check, not an independent semantic validation of plausibility.

3. 'Parallel requests and rate limiting affect speed, not what is sent' should be limited to request content. Scheduling can change retry patterns, failures and missingness, even if model IDs, prompt text and sampling parameters stay fixed. Prefer 'Earlier scheduling variants are reported to change concurrency and rate limiting, while leaving request content and sampling parameters unchanged.' Avoid claiming these differences could only affect runtime.

4. The new README says replaying 400 Experiment 2 records through the recovered historical file yields zero differences. The supplied replay_check.py remains unchanged and imports only top-level fliprate.py. It does not reproduce that specific historical-version check. Include the command/checker that selects the archived Experiment 2 module, or clearly state that this was a separately performed check. A strengthened verifier can substantiate it now without any API calls.

5. Keep collection-time parsing separate from later analytical scoring. The shared scoring.py corrections changed post-processing of unknown endings on 15 November. Saying earlier 'scoring is unchanged' should refer precisely to parsed record fields and conversation behavior, not imply that the released aggregate analysis always used its corrected missing-output rule.
